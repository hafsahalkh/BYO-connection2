# Specode React Convex Scaffold

Blank frontend scaffold for Convex apps. The backend and auth wiring stay in
place, but the product UI is intentionally removed so each new app can be
designed from scratch.

## Commands

```bash
pnpm dev            # Start Convex + Vite dev servers (http://localhost:5173)
pnpm dev:vite       # Start Vite dev server only
pnpm dev:convex     # Start Convex dev server + Vite concurrently
pnpm build          # Deploy Convex and build for production
pnpm deploy:static  # Deploy frontend assets to Convex static hosting
pnpm lint           # TypeScript check + ESLint
```

> **Note:** This template uses pnpm v8 (`packageManager` field in package.json). When developing locally, you can use newer pnpm versions. However, Specode AI Coder runs on WebContainers which use pnpm 8.15.6 - keeping the lockfile compatible with v8 ensures faster installs and avoids compatibility warnings.

## Scaffold

- `src/App.tsx` is the only frontend screen and is meant to be replaced.
- No product pages, dashboard, or starter design system are included.
- Add routing only if the app actually needs multiple screens.
- Keep the Convex backend files in `convex/` and build the frontend around them.
- Project memory lives in `memory/` with:
  - `memory/roadmap.md`
  - `memory/design-brief.md`
  - `memory/user-input/`
- Keep the memory folder structure stable so orchestration can write planning
  artifacts predictably across new projects.

## Styling (Tailwind v4)

Tailwind is enabled via `@tailwindcss/vite`. Global styles live in
`src/index.css`. Keep the initial scaffold neutral and create product-specific
styles when building the app.

## Path Aliases

Use `@/` as an alias for `src/`:

```typescript
import { convex } from "@/lib/convex";
import { authClient } from "@/lib/auth-client";
```

**Case-sensitive imports:** WebContainers and production Linux filesystems are case-sensitive. Ensure import casing matches filenames exactly or Vite will fail to resolve the module.

## Convex

Client setup: `src/lib/convex.ts` exports the `convex` client, wrapped in
`ConvexBetterAuthProvider` in `src/main.tsx` when Convex is configured.

## Auth (Better Auth)

This project uses **Better Auth** with the **Convex Better Auth component** for
email/password auth plus password reset via email OTP codes, and a cross-domain cookie flow for
Convex auth tokens. Client wiring is in `src/lib/auth-client.ts`, server wiring
is in `convex/auth.ts`, and routes are registered in `convex/http.ts`.

### Auth setup (first-time)

Generate a Better Auth secret and set it in Convex:

```bash
openssl rand -base64 32 | tr -d '\n' | npx convex env set BETTER_AUTH_SECRET
```

> Keep this secret stable across deploys. Rotating it invalidates sessions.

Set the frontend URL:

```bash
npx convex env set SITE_URL "http://localhost:5173"
```

Set Mailgun credentials:

```bash
npx convex env set MAILGUN_API_KEY "your-mailgun-api-key"
npx convex env set MAILGUN_DOMAIN "your-mailgun-domain"
npx convex env set AUTH_EMAIL "postmaster@your-mailgun-domain"
npx convex env set AUTH_EMAIL_NAME "Your App"
```

> For Mailgun sandbox domains, `AUTH_EMAIL` must be `postmaster@sandbox....mailgun.org`. Add recipient emails as Authorized Recipients in the Mailgun dashboard before testing.

When a project is provisioned through Specode V2, auth emails can also use a
Specode-managed Mailgun relay out of the box. If you later set
`MAILGUN_API_KEY`, `MAILGUN_DOMAIN`, and `AUTH_EMAIL` for your own domain, the
template will bypass the relay and send directly with your Mailgun account.

### Local development notes

- `VITE_CONVEX_SITE_URL` is auto-set in `.env.local` by `npx convex dev` to the local HTTP actions port (`http://127.0.0.1:3211`). The auth client reads this for local deployments — do not set this variable in your cloud/production environment.
- The Convex local backend runs two ports: `3210` (queries/mutations) and `3211` (HTTP actions / auth routes). Auth requests must go to `3211`.

### Production env vars (required)

Convex / server:
- `BETTER_AUTH_SECRET` - Strong secret (32+ chars). Required.
- `MAILGUN_API_KEY` - Mailgun API key for sending auth emails.
- `MAILGUN_DOMAIN` - Mailgun sending domain (e.g., `mg.example.com`).
- `AUTH_EMAIL` - From-address for reset emails (must be a verified sender in Mailgun).
- `AUTH_EMAIL_NAME` - Optional sender display name.
- `SITE_URL` - Your frontend URL. Required in production for cross-domain flows.

Client / browser:
- `VITE_CONVEX_URL` - Convex deployment URL (auto-generated by `npx convex dev`).

### CORS note

Auth routes are registered with `{ cors: true }` in `convex/http.ts`. This is
convenient for dev, but you may want to restrict allowed origins in production.

### Cross-domain session loop fix

The default cross-domain client triggers a session refetch whenever it receives
`Set-Better-Auth-Cookie` — including `/get-session` responses. The Convex Better
Auth plugin sets a JWT cookie on `/get-session`, which can cause a refetch loop.

We use a small local wrapper in `src/lib/cross-domain-client.ts` that skips the
refetch notification for `/get-session` responses. This keeps auth reactive
without continuous `/get-session` requests.

### Maintenance note

`src/lib/cross-domain-client.ts` is a small wrapper based on the upstream
cross-domain client. If you upgrade `@convex-dev/better-auth` or `better-auth`,
review upstream changes and re-sync if needed.

### Getting Started

```bash
npx convex dev   # Initialize project, set up env vars, start dev server
```

This creates a `.env.local` file with `VITE_CONVEX_URL` automatically.

### Environment Variables

Client-side (browser):
- `VITE_CONVEX_URL` - Convex deployment URL (auto-generated)

Server-side (Convex functions):
```bash
npx convex env set API_KEY "your-secret-key"
```

**Note:** Do not expose API keys to the browser. Use Convex environment variables for server-side secrets.

### Backend Functions

Define your schema in `convex/schema.ts` and create functions in the `convex/` directory:

```typescript
// convex/tasks.ts
import { query, mutation } from "./_generated/server";
import { v } from "convex/values";

export const list = query({
  handler: async (ctx) => {
    return await ctx.db.query("tasks").collect();
  },
});

export const create = mutation({
  args: { text: v.string() },
  handler: async (ctx, args) => {
    await ctx.db.insert("tasks", { text: args.text, isCompleted: false });
  },
});
```

### React Hooks

```typescript
import { useQuery, useMutation } from "convex/react";
import { api } from "../convex/_generated/api";

const tasks = useQuery(api.tasks.list);
const createTask = useMutation(api.tasks.create);
```
